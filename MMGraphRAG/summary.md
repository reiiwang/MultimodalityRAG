# RAG-Anything 與 MMGraphRAG 論文比較報告

---

## 1. 兩篇文章要解決的問題

傳統 RAG／GraphRAG 系統**只能處理純文字**，但真實世界的文件（學術論文、財報、新聞、法律文件等）本質上是**多模態**的，同時包含文字、圖片、表格、公式等內容。

這造成了共同的核心痛點：

- 現有系統要嘛**捨棄非文字資訊**，要嘛**把圖表硬轉成文字描述**，導致資訊嚴重流失
- 無法回答「需要看圖 / 看表才能回答」的問題（例如：比較圖表中哪個模型表現較好、財報表格中特定欄位的數值）
- 在**長文件**（100 頁以上）場景下，相關證據分散在不同模態與不同段落，傳統文字檢索難以定位

> 兩篇論文都選擇「建立能融合文字與視覺資訊的知識圖譜」這條路線，並且使用**相同的評測基準**（DocBench、MMLongBench），甚至互為對方論文中的比較 baseline。

---

## 2. 兩篇論文的解決概念、範圍與解法

### 2.1 RAG-Anything（HKU, 2025）

**核心概念**：把所有模態（文字/圖片/表格/公式）都當作「原子知識單元」，用**雙圖架構**統一表示，再做跨模態混合檢索。

**涵蓋範圍**：文字、圖片、表格、公式 —— **全模態**，範圍最廣。

**解法（三階段）**：
![alt text](image-1.png)
| 階段 | 做法 |
|---|---|
| **知識統一化** | 用專門解析器（MinerU）將文件拆成 atomic unit，每個 unit 用 VLM/LLM 生成「詳細描述」+「實體摘要」，並考慮上下文鄰域 |
| **雙圖構建** | ① **Cross-Modal KG**：以非文字單元為錨點建圖，保留視覺元素的結構關係（如表格 header↔cell、圖表 panel↔caption） <br> ② **Text-based KG**：沿用 LightRAG/GraphRAG 的傳統文字圖譜 <br> 兩圖透過**實體對齊**合併成統一圖譜 |
| **跨模態混合檢索** | **結構化導航**（圖上多跳關係）+ **語義相似度匹配**（向量檢索）雙路並行，再做融合排序，最後交給 VLM 生成答案 |

**特點**：創新分布在「索引建構」與「檢索」兩端；特別擅長**長文件**與**結構複雜的表格/多面板圖**（案例顯示能正確定位表格行列交叉點、辨識多面板圖中的正確子圖）。

---

### 2.2 MMGraphRAG（HIT & NTU, 2025）

**核心概念**：把圖像轉成 **Scene Graph**（場景圖），再透過一個專門設計的**跨模態實體連結方法 SpecLink**，將圖像實體與文字實體對齊融合成統一的 MMKG。

**涵蓋範圍**：主要聚焦**文字＋圖像**兩種模態（表格、公式仍當作純文字處理，未特別建模）。

**解法（核心是 CMEL 任務）**：

![alt text](image.png)
| 步驟 | 做法 |
|---|---|
| **Image2Graph** | YOLO 語意分割圖片 → MLLM 為每個區塊生成描述 → 抽取實體與關係（含隱含關係，如「兩人靠得很近，可能是情侶」）→ 建立全域實體代表整張圖 |
| **Text2Graph** | 沿用傳統 GraphRAG 方式建立文字知識圖譜 |
| **Cross-Modal Fusion（核心創新）** | 用 **SpecLink**：重新設計加權鄰接矩陣（同時考慮語義相似度＋關係權重）做**譜聚類（spectral clustering）**，為每個視覺實體產生候選文字實體集合，再用 LLM 做最終對齊判斷。相較 KMeans／DBSCAN／PageRank 等方法，能同時利用語義與圖結構資訊，準確率明顯更高 |
| **檢索與生成** | 沿路徑（reasoning path）檢索融合後的 MMKG，並用 LLM＋MLLM 混合生成答案 |

**額外貢獻**：由於 CMEL（跨模態實體連結）任務缺乏標準評測，作者額外建構並釋出 **CMEL 資料集**（新聞／學術／小說三領域），專門評測實體對齊品質。

**特點**：創新集中在「**如何把圖像實體與文字實體正確配對**」這個單一但關鍵的技術難點；在**辨識「無法回答」問題**（避免幻覺）上表現特別突出。

## 3. 兩者對照小結

| 面向 | RAG-Anything | MMGraphRAG |
|---|---|---|
| 涵蓋模態 | 文字＋圖片＋表格＋公式（全模態） | 文字＋圖片（表格/公式仍為純文字） |
| 創新重點 | 雙圖架構 ＋ 跨模態混合檢索（索引與檢索兩端） | SpecLink 跨模態實體連結（譜聚類），聚焦圖譜融合階段 |
| 額外貢獻 | 無新資料集 | 發布 CMEL 資料集，專測跨模態實體對齊 |
| 相對優勢 | 長文件、複雜表格/多面板圖定位 | 抑制幻覺、辨識不可回答問題 |
| 兩篇互評 | 論文中將 MMGraphRAG 列為 baseline，整體準確率略勝 | 論文中亦將 RAG-Anything 前身概念相關方法列為對照 |

> **一句話總結**：兩篇論文要解決的問題完全一致（多模態文件的 RAG 問答），但 RAG-Anything 走的是「**全模態統一框架**」路線，創新點分散在索引與檢索兩階段；MMGraphRAG 走的是「**精準圖文實體對齊**」路線，把主要心力集中在 SpecLink 這一個技術突破點上，並用新資料集驗證。

## 4. 更深一層的共同點：兩者都是「雙圖 → 融合」範式

如果再往架構本質看，會發現兩篇論文其實走的是**同一套範式**：

```
文字資料 → Text-based KG  ┐
                          ├→ 融合 → 統一 MMKG → 檢索 → 生成
視覺資料 → Visual/Cross-modal KG ┘
```

差異在於「融合」這一步做得**多細**、以及論文把力氣**花在哪個環節**。

### RAG-Anything：融合手段較「粗」，重心在融合之後

- Cross-modal KG 的建圖方式：每個非文字 unit（圖/表/公式）先用 VLM 生成描述，再用一般的 entity/relation 抽取器（論文公式 2 的 `R(·)`）在描述上跑一次，產生實體
- 融合步驟（2.2.2 節）直接說明：**用實體名稱作為主要匹配鍵**（entity names as primary matching keys）來對齊兩張圖，做法相對直白
- 也就是說，它的技術重心**不在融合演算法本身**，而是放在「怎麼把圖表結構化」以及「融合完之後怎麼做跨模態混合檢索」（結構導航 + 語義匹配雙路並行）這兩件事上

### MMGraphRAG：融合本身就是整篇論文的主戲

- 明確把「圖文實體融合」定義成一個獨立任務 —— **CMEL（Cross-Modal Entity Linking）**，並專門建構、釋出新資料集來驗證
- 融合演算法不是單純比對名字，而是：
  1. 重新設計加權鄰接矩陣（語義相似度 × LLM 判斷的關係權重）
  2. 用**譜聚類**先縮小候選池（因為文字實體數量遠多於視覺實體，直接兩兩比對效率低、也容易誤配）
  3. 再用 LLM 在候選池中做最終判斷
- 消融實驗（4.3.1 節）證實：若把 SpecLink 換成「embedding 相似度超過閾值就融合」的 naive 做法，幻覺率明顯上升（在「無法回答」問題上準確率掉了 9.7 個百分點），證明**融合品質本身就是效能瓶頸**，而非可以隨意帶過的步驟

### 核心對比一句話

> 兩篇都採「先各自建圖、再融合」的範式，但 **RAG-Anything 把力氣花在融合完之後的檢索**（結構導航 + 語義匹配雙路），假設「圖建好、對齊沒那麼難」；**MMGraphRAG 把力氣花在融合這一步本身怎麼做得更準**（SpecLink），認為「跨模態實體對齊本身就是個沒被解決好的難題」，並用一整篇論文與新資料集去攻這一點。
