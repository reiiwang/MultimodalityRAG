# Problem statement


## 一、觀察到的目前困境

**1. 純文字 RAG 的侷限**
- 傳統 RAG 讓 LLM 透過檢索外部知識庫來補充生成時所需的上下文，減少因參數化知識不足而產生的幻覺
- 但現實世界中大量知識存在於**非文字模態**（圖片、表格、複雜文件版面）中

**2. 前處理路線的資訊損失**
- 若先用 OCR 或圖說（captioning）把視覺內容「線性化」轉成文字，再餵給 LLM，會**不可避免地丟失關鍵的視覺與空間線索**，模型無法真正接觸到原始圖像中的資訊

**3. Visual RAG（VRAG）雖然改善了這點，但仍有新問題**
- 現有 VRAG 方法多半只是把「文字版 RAG 的做法」直接搬到視覺領域，**忽略了視覺模態特有的需求**，例如：
  - 跨圖像的證據對齊（cross-image grounding）
  - 版面感知式閱讀（layout-aware reading）
  - 區域級別的注意力（region-level attention）
- 結果就是：當檢索到**多張圖片**時，模型常常**無法可靠地跨圖感知與整合資訊**

**4. 現有解法的代價過高**
- 有些方法引入「感知導向的動作」或「輔助代理（agent）」來引導推理，雖然能提升對視覺細節的關注，但會**增加架構複雜度與計算成本**，讓端到端訓練和後續調整變得困難

**5. 單圖推理模型（VLRM）無法直接套用到多圖場景**
- 近期視覺語言推理模型（VLRM）雖然在**單張圖片**的感知強化上表現不錯（透過輔助獎勵機制），但 VRAG 通常需要**同時處理多張檢索圖片**，需要跨圖定位與整合細粒度證據
- 目前方法**缺乏內建的逐圖證據蒐集機制**，只能依賴外部工具或代理，導致系統更複雜、更不穩定

**6. 訓練層面的獎勵設計問題**
- 現行 VLRM 訓練策略通常用「混合獎勵」同時優化感知與推理，**沒有區分每個獎勵訊號的作用範圍與目標差異**，導致 **credit assignment（獎勵歸因）模糊**，感知與推理兩種能力互相干擾

---

## 二、具體想解決的問題

> **如何讓 VLM 在多圖檢索場景下，具備精確的視覺感知能力，能跨圖定位並整合細粒度證據，同時不需要依賴外部工具/代理，並且訓練時能清楚區分「感知」與「推理」兩種能力的獎勵訊號，避免互相干擾。**

---

## 三、解決方法

### 1. EVisRAG 框架（模型行為設計）
- 讓模型執行一個**「語言化觀察階段」（linguistic observation phase）**：
  - 依序逐張檢視檢索到的圖片
  - 針對每張圖片記錄下相關證據（evidence）
  - 保持對每張圖片的專注
- 接著進入**推理階段**，基於已蒐集的所有證據進行推理，得出最終答案
- 這個過程**內建在模型本身**，不需要外部代理或工具

### 2. RS-GRPO 訓練方法（獎勵機制設計）
- 全名：**Reward-Scoped Group Relative Policy Optimization**
- 核心概念：把**細粒度的獎勵訊號，精準綁定到對應範圍（scope）的 token 上**
  - 例如：「感知獎勵」只作用在記錄證據的 token 上
  - 「推理獎勵」只作用在最終推理/回答的 token 上
- 這樣可以**同時優化感知能力與推理能力，且互不干擾**，解決前述 credit assignment 模糊的問題


EVisRAG 訓練出來的模型，在生成回答的過程中會遵循固定的**兩階段輸出結構**：

```
[觀察階段] → 逐張圖片記錄證據 (per-image evidence)
    ↓
[推理階段] → 基於彙整後的所有證據進行推理
    ↓
[最終答案]
```

具體來說：
- **不是**額外接一個「觀察模組」或「代理」去看圖，而是**同一個模型**，在生成文字序列時，會先產生類似「證據記錄」的文字段落（針對每張檢索圖片各自寫下相關資訊），然後才產生推理與最終答案
- 這整個「先觀察記錄證據、再推理作答」的行為模式，是透過 **RS-GRPO** 訓練出來的——因為獎勵訊號分別綁定在「證據記錄」對應的 token 範圍和「推理/答案」對應的 token 範圍上，模型才學會穩定地依照這個順序來組織輸出
- 論文中把這個行為比喻成「偵探辦案」：**先逐一蒐證（per-image evidence），再根據蒐集到的線索推理出結論**，而不是看完所有圖片後直接「憑印象」給答案

這種設計的好處是：答案的推理過程有清楚的**證據鏈可追溯**，比起黑箱式的「看圖直接回答」，更能降低幻覺、提升多圖場景下的準確度。

EVisRAG 三階段筆記

## 整體架構

EVisRAG 把「多圖 VRAG 回答問題」拆成 **4 個依序生成的階段**，前一階段的輸出會成為下一階段的條件輸入，形成一條完整的機率鏈：

$$D_R \to r_{observe} \to r_{evidence} \to r_{reason} \to r_{answer}$$

---

## 階段 1｜資訊蒐集 Information Gathering（公式 2）

$$D_R = \text{VisRAG}(q, D)$$

- 根據問題 $q$，從語料庫 $D$ 中檢索出 **top-k 相關頁面** $D_R$
- 採用既有的 VisRAG 檢索方法，這一步是純檢索，還沒進入 VLM 推理

## 階段 2｜視覺感知 Visual Perception（公式 3、4）

**(a) 整體觀察**：模型看過所有檢索頁面 $D_R$，寫出一段粗略、整頁層級的描述 $r_{observe}$

**(b) 逐圖取證**：針對每一張圖片 $d_i$，各自生成一段對應的證據 $r_{evidence}^{(i)}$
- 重點：這一步**每張圖分開處理**，且每次都重新看回原圖 $d_i$，不是只憑摘要腦補

> 💡 這階段像「先掃過全部證物，再逐一貼上標籤」

## 階段 3｜答案推理 Answer Reasoning（公式 5）

$$r_{reason} \sim P(\cdot \mid q, r_{perception}, D_R)$$

- 基於前面蒐集的感知資訊 $r_{perception} = \{r_{observe}, r_{evidence}\}$，模型進行「偵探式推理」：
  - 從證據中提煉線索
  - 跨頁提出並驗證假設
  - 交叉檢查是否矛盾
- 條件項中**依然保留原始圖片 $D_R$**，不是只靠文字推理

## 階段 4｜生成答案 Final Answer（公式 6）

$$r_{answer} \sim P(\cdot \mid q, r_{perception}, r_{reason}, D_R)$$

- 綜合「問題 + 感知 + 推理 + 原始圖片」，生成最終答案
- 圖片全程沒有離開條件，保留了模型隨時回頭核對原圖的能力

---

## 一句話總結

**檢索 → 觀察 → 取證 → 推理 → 作答**，每一步都是前一步的延伸，且圖片 token 全程保留在條件中，讓模型能像偵探辦案一樣「先蒐證、再推理、最後下結論」，而不是看一眼圖就急著回答。


# RS-GRPO 訓練方法解析

這節在講：前面 4 個階段的架構設計好了，但**要怎麼訓練模型，才能讓它真的乖乖照這個流程走、而且做得好**？答案就是 RS-GRPO。

## 訓練分兩階段

1. **SFT（監督微調）當冷啟動**：先讓模型學會基本的「觀察→證據→推理→答案」格式
2. **RS-GRPO**：在 SFT 基礎上用強化學習進一步優化，**同時**加強「感知能力」和「推理能力」

---

## 三種獎勵（Reward Scopes）

| 獎勵 | 檢查什麼 |
|---|---|
| $R_{format}$ | 是否按照「觀察→記錄證據→推理→回答」的**固定順序**輸出，格式有沒有守規矩 |
| $R_{perception}$ | 每張圖的**證據有沒有抓對重點**（跟一個更大的 VLM 生成的 ground truth 證據比對），如果圖片根本沒有相關資訊，也允許模型誠實地說「沒有相關資訊」 |
| $R_{derivation}$ | 最終答案有沒有**正確地從證據推導出來**，確保推理有真的紮根在前面記錄的證據上 |

## 核心創新：獎勵不是「整段打分」，而是「精準對應到特定 token」

這是這篇論文的關鍵貢獻。過去的做法通常是：模型輸出一整段話，最後給一個總分，這樣的問題是——**分不清楚是「觀察沒觀察好」還是「推理沒推理好」**，兩種能力的訓練訊號混在一起、互相干擾。

RS-GRPO 的解法：把輸出序列切成 **4 個 scope（範圍）**，每個 scope 只接受對應的獎勵：

$$\mathcal{M}(t) = \begin{cases} \{R_{perception}, R_{format}\} & t \in \mathcal{T}_o \cup \mathcal{T}_e \\ \{R_{derivation}, R_{format}\} & t \in \mathcal{T}_r \cup \mathcal{T}_a \end{cases}$$

白話翻譯：

- **觀察範圍 $\mathcal{T}_o$ + 證據範圍 $\mathcal{T}_e$**（也就是「看圖、寫證據」的那些字）→ 只吃 $R_{perception}$（看得準不準）+ $R_{format}$（格式對不對）
- **推理範圍 $\mathcal{T}_r$ + 答案範圍 $\mathcal{T}_a$**（也就是「推理、下結論」的那些字）→ 只吃 $R_{derivation}$（推得對不對）+ $R_{format}$

**用比喻理解：** 這就像老師改考卷時，不是整張卷子打一個總分，而是「計算過程」跟「最終答案」分開評分——算式寫錯了扣感知分,答案算錯了扣推理分,兩邊訊號不會混在一起，模型才知道具體哪裡要改進。

## 怎麼把獎勵變成訓練訊號

**Step 1：同一個 token 位置的多個獎勵先取平均（公式 8）**

$$\bar{R}_t^i = \frac{1}{|\mathcal{M}(t)|} \sum_{m \in \mathcal{M}(t)} R_t^{(m),i}$$

比如觀察範圍的某個 token，同時有 $R_{perception}$ 和 $R_{format}$ 兩個分數，就取平均當作這個 token 的獎勵。

**Step 2：跟同一批（group）裡其他樣本比較，算出「優勢」（公式 9）**

$$\hat{A}_t^i = \frac{\bar{R}_t^i - \text{mean}(\{\bar{R}_t^1, ..., \bar{R}_t^G\})}{\text{std}(\{\bar{R}_t^1, ..., \bar{R}_t^G\})}$$

這是標準 GRPO 的做法：對同一個問題，模型生成 $G$ 個不同的回答，看某個 token 的獎勵**比同組平均高還是低**（做標準化），高於平均就鼓勵模型多產生類似的 token，低於平均就抑制。

**Step 3：套入 DAPO 目標函數做最終優化（公式 10）**

$$\mathcal{L}_{RS\text{-}GRPO}(\theta) = -\frac{1}{\sum_{i=1}^G |o^i|} \sum_{i=1}^G \sum_{t=1}^{|o^i|} \min\left(r_t^i(\theta)\hat{A}_t^i, \text{clip}(r_t^i(\theta), 1-\epsilon_{low}, 1+\epsilon_{high})\hat{A}_t^i\right)$$

這是標準的 PPO 風格 clipped objective（借用 DAPO 的作法），用 clip 機制避免模型一次更新幅度過大、訓練不穩定。這部分不是這篇論文的創新重點，是站在既有 RL 方法上做整合。

---

## 這如何呼應你之前的疑慮

還記得你之前問「模型有沒有真的利用圖片，還是只是形式上放著」嗎？**這一節就是答案的關鍵**：

- 光有公式 (3)~(6) 的架構，只保證模型「**可以**」看圖，不保證它「**真的會好好看**」
- $R_{perception}$ 這個獎勵訊號，就是**強迫**模型在觀察/證據階段，真的把圖片內容講對（跟大模型生成的 ground truth 證據比對），如果亂寫或漏看重點就會被扣分
- 而且因為獎勵是**精準綁定在對應 token 範圍**，不會被推理階段的獎勵訊號稀釋或干擾，這樣「看圖能力」才能被扎實地訓練出來,而不只是流於形式
